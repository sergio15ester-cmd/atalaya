## Procedimiento

1. Consultar estado, permisos y rama por defecto del repositorio; verificar acceso de lectura y escritura. Si falta escritura, esperar sin intentar modificar visibilidad ni permisos.
2. Buscar una PR o rama previa de esta entrega para evitar duplicados. Rama propuesta: docs/propuestas-negocio-2026-10-08. Título: Propuestas económicas y experimentos de Atalaya.
3. Leer AGENTS.md y documentación aplicable del estado actual. Verificar PR de fundación y no mezclar su código con esta entrega.
4. Crear la rama documental desde la rama por defecto actual. Estos documentos son independientes del código; no requieren integrar antes la PR de fundación.
5. Añadir solo los archivos de este paquete bajo docs/propuestas y templates/propuestas. Si hay colisiones, comparar y preservar cambios; no sobrescribir trabajo reciente.
6. Confirmar que no se incluyan nombres, profesiones de integrantes, aportes reales, datos bancarios, credenciales, reportes internos ni rutas locales. Importes del documento económico son escenarios comerciales hipotéticos, no aportes reales.
7. Verificar enlaces internos, esquema JSON, diff y ausencia de cambios fuera de alcance. Para una PR solo documental no hace falta instalar dependencias ni ejecutar pruebas financieras.
8. Abrir PR en borrador con problema, contenido, evidencia, limitaciones y verificaciones. No fusionar ni solicitar revisores individuales sin una instrucción adicional.
9. Devolver URL y resumen al usuario; detener el seguimiento después de confirmar la PR.

El informe interno con presupuesto y perfiles del equipo NO forma parte de este paquete y no debe incorporarse automáticamente, aunque el repositorio ya sea privado. No interpretar la documentación propuesta como decisión de comenzar a vender servicios.

Si el acceso desaparece al hacerse privado, informar del bloqueo de conexión y esperar configuración; no crear un fork público como alternativa.
